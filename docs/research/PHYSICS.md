# Физика полёта DroneSim — спецификация

> Цель: пилот, налетавший в DroneSim, садится за реальный дрон и «узнаёт» его: тот же отклик на стики, та же инерция, та же просадка батареи, тот же пропвош. Всё ниже — для реализации в `app/src/sim/` (TypeScript). Единицы СИ. Ось мира: **+Y вверх, −Z вперёд** (three.js / glTF). Тело дрона: **+X вправо, +Y вверх (ось тяги), −Z нос**.

---

## 0. Общая схема цикла

```
 ввод (клавиатура/тач/геймпад/RC, 60–250 Гц)
   └─► RC-фильтр + rates (Betaflight/Actual/DJI)  ─► setpoint (град/с или углы/скорости)
         └─► полётный контроллер (PID, mixer, airmode, TPA, idle)  @ 1000 Гц
               └─► ESC/моторы (электромеханика, τ, просадка)       @ 1000 Гц
                     └─► пропеллеры (тяга, момент, H-сила, VRS/пропвош, ground effect)
                           └─► твёрдое тело 6DoF + аэродинамика корпуса + ветер
                                 └─► коллизии (Rapier) / повреждения
 рендер 60–144 Гц с интерполяцией между шагами физики
```

* **Фиксированный шаг физики `dt = 1/1000 с`** (на слабых телефонах допускается 1/500 — профиль качества). Аккумулятор времени, максимум 40 подшагов за кадр, иначе — slow-motion вместо «взрыва» симуляции.
* Интегратор: **полу-неявный Эйлер** (symplectic) для скорости/позиции + кватернион ориентации, нормализация каждый шаг. Для моторов — точное решение линейной ОДУ первого порядка (`exp(-dt/τ)`), а не Эйлер.
* Детерминизм: один и тот же входной поток → одинаковый результат (нужно для реплеев, «призраков» и тестов). Никакого `Math.random()` в физике — только сидовый PRNG (`mulberry32`) на сессию.

## 1. Твёрдое тело (6DoF)

Состояние: `p` (м), `v` (м/с, мир), `q` (кватернион тело→мир), `ω` (рад/с, **в осях тела**).

```
F_world = Σ R(q)·F_body_i + m·g + F_drag_body + F_wind + F_contact
τ_body  = Σ (r_i × F_i) + Σ τ_reaction_i + τ_gyro + τ_aero_damping
v̇ = F_world / m
ω̇ = I⁻¹ · (τ_body − ω × (I·ω))         # уравнения Эйлера, I — диагональный тензор инерции
q̇ = ½ · q ⊗ (0, ω)
```

* `g = 9.80665 м/с²`, плотность воздуха `ρ = 1.225 кг/м³` (на уровне моря, 15 °C). В настройках карты можно задать высоту над уровнем моря и температуру → `ρ = p/(R·T)` (влияет на тягу! в горах дрон «вялый»).
* Инерция — из пресета дрона (см. `DRONES.md`); при наличии подвеса/груза — пересчитывается (Штейнер).
* Гироскопический момент роторов: `τ_gyro = −ω × (J_r · Σ s_i·Ω_i · ŷ)`, где `J_r` — момент инерции ротора+колокола, `s_i = ±1` — направление вращения. Заметен на 7"–10" при резких вращениях.

## 2. Мотор + ESC + батарея (электромеханическая модель)

Это то, что даёт «живой» отклик газа, просадку к концу пака и разницу между 4S/6S.

### 2.1 Мотор (BLDC outrunner)
```
Kv_rad = KV · 2π/60            # (рад/с)/В
Ke = 1/Kv_rad   (В·с/рад),  Kt = Ke  (Н·м/А)
I_m   = (d · V_bus − Ke·Ω) / R_m          # d — duty (0..1) от ESC
τ_m   = Kt·(I_m − I_0)                    # I_0 — ток холостого хода
J_r · Ω̇ = τ_m − τ_prop(Ω) − b·Ω           # τ_prop = k_Q·Ω²
```
* Типичные значения: 2306 1750KV — `R_m ≈ 0.07 Ом`, `I_0 ≈ 1.2 А`, `J_r ≈ 1.6e-5 кг·м²` (с пропеллером 5.1"). 2806.5 1300KV — `R_m ≈ 0.06`, `J_r ≈ 3.5e-5`. 3115 900KV — `R_m ≈ 0.05`, `J_r ≈ 1.1e-4`.
* Отсюда автоматически получаем **время разгона** (τ ≈ 15–25 мс у 5", 40–60 мс у 7", 80–120 мс у 10" и камерных дронов) — не задаём τ руками, а получаем из физики; для дешёвого режима на слабых устройствах допустима упрощённая модель `Ω̇ = (Ω_cmd − Ω)/τ`.
* **Торможение**: ESC с DShot и bidirectional + «damped light» → активное торможение, `τ_brake ≈ 0.6·τ_accel`. Без него (камерные дроны, FOC-ESC с мягкой настройкой) — торможение только за счёт `k_Q·Ω²`.
* **Motor idle** (Betaflight `dshot_idle_value` ≈ 5.5 %): моторы крутятся при газе 0 в армленном состоянии → можно управлять ориентацией при нулевом газе (airmode).
* Нагрев мотора/ESC (опционально, этап 4): `T += (I²R − h·(T−T_amb))·dt/C`; при 120 °C — деградация (снижение КПД), предупреждение в OSD.

> **Реализация (Этап 2, `app/src/sim/motor.ts`)**: в знаменателе не `R_m`, а импеданс обмотки `Z(Ω) = √(R_m² + (p·L·Ω)²)` (p — пары полюсов, `motor.poles`, `L_uH`): чистая `R_m = 0.07` давала бы >100 А на полном газу у 2306, а реактанс на электрической частоте держит ток на стендовых 40–45 А (6S). Ток фазы ограничен `motor.i_max` (лимит ESC/насыщение железа — ESC снижает эффективную скважность). Активное торможение = ток может менять знак (рекуперация); без него ток только приводной, ротор выбегает на `k_Q·Ω²`. Мотор и батарея решаются совместно каждый шаг: ток шины линеен по `V_bus` → замкнутая формула, без алгебраической петли. Время отклика 5" у висения ≈ 20 мс (тест). `simple_motor_model` (Gazebo) — прежний `exp(-dt/τ)`, `Ω_cmd ∝ V_bus`, ток пакета из механической мощности.

### 2.2 Батарея (LiPo/Li-ion, модель Тевенина)
```
V_oc = cells · OCV(SoC)              # таблица OCV: 4.20 В (100%) … 3.70 (50%) … 3.30 (0%) на банку
V_bus = V_oc − I_tot·R_int − V_rc
V̇_rc = I_tot/C_p − V_rc/(R_p·C_p)   # поляризация: «отскок» напряжения после броска газа
SoC  -= I_tot·dt / (3600·Capacity_Ah)
```
* `R_int` на банку: LiPo 1100–1300 мА·ч 6S ≈ 6–9 мОм (хороший пак) … 15 мОм (уставший); Li-ion 21700 ≈ 15–25 мОм (сильная просадка на панче!). `R_p ≈ R_int`, `R_p·C_p ≈ 2–5 с`.
* Ток пакета `I_tot = Σ I_m / η_esc + I_avionics` (`I_avionics ≈ 0.6–1.5 А`: VTX, камера, приёмник).
* **Что видит игрок**: на OSD — `V_bus`, mAh, просадка при панче (6S: с 25.0 до 21–22 В), к концу пака дрон заметно слабее (макс. обороты ∝ V_bus). LVC-предупреждение 3.5 В/банку под нагрузкой; при 3.0 В/банку — ESC-отсечка (реалистичный «пак сел — падаем»).
* Камерные дроны (Mavic-класс): умная батарея — показываем %, RTH-при-низком-заряде, принудительная посадка ≤ 10 %.

---

> **Реализация (`app/src/sim/battery.ts`)**: `V_oc` — таблица *равновесного* OCV (LiPo: 4.20 / ≈3.84 при 50 % / 3.30; Li-ion: 4.20 / 3.69 / 2.80), т.к. просадка под нагрузкой считается отдельно `R_int` и RC-веткой (табличные «3.70 при 50 %» — это уже напряжение под нагрузкой). `R_p = rp_ratio·R_int`. Ток шины `I = Σ d_i·I_m,i/η_esc + I_av` (ESC — понижающий преобразователь: на висении ток фазы ≈ 7 А, а из пакета ≈ 1.6 А на мотор). Под конец пака `R_int` растёт (×2.5 при SoC 0). OSD показывает `V_bus` через PT1 0.5 с, предупреждение LVC — по фильтру 3 с (как vbat-фильтры BF). Отсечка ESC: ниже `cutoff` (LiPo 3.0, Li-ion 2.7 В/банку) скважность плавно урезается, при SoC 0 — моторы стоп. Калибровка 5" freestyle: `r_cell 3.6 мОм` (хороший 120C-пак по зарядке 2–4 мОм), `rp_ratio 0.4`.

## 3. Пропеллер

### 3.1 Тяга и момент (статика + поправка на поток)
```
T_i = k_T(J) · Ω_i²       ,   Q_i = k_Q(J) · Ω_i²
J   = V_axial / (n·D)     # advance ratio, n = Ω/2π, V_axial — скорость набегающего потока вдоль оси ротора (вверх = +)
k_T(J) = k_T0 · max(0, 1 − J / J_0)        # линейное падение тяги с осевой скоростью; J_0 ≈ pitch/D · 1.1
k_Q(J) = k_Q0 · (1 − 0.6·J/J_0)
```
* Связь с паспортом винта: статический `C_T ≈ 0.14–0.18` (трёхлопастные 5"), `0.10–0.12` (двухлопастные), `C_P ≈ 0.07–0.10` / `0.04–0.06`; `k_T0 = C_T·ρ·D⁴/(4π²)`, `k_Q0 = C_P·ρ·D⁵/(8π³)`. Отношение `k_Q/k_T ≈ 0.011–0.016 м` (в Gazebo — `momentConstant`).
* Пример 5" (5.1×3.6×3, D = 0.1295 м): `k_T0 ≈ 1.45e-6 Н/(рад/с)²`, `k_Q0 ≈ 1.6–2.4e-8 Н·м/(рад/с)²`. Для дронов из Gazebo (x500, Iris, Typhoon, VTOL) берём реальные `motorConstant`, `momentConstant`, `timeConstantUp/Down`, `rotorDragCoefficient` из их `model.sdf` (см. `assets/presets/drones.json`). На 6S без нагрузки `Ω_max ≈ 1750·25.2·2π/60 ≈ 4620 рад/с`, под нагрузкой ≈ 3400–3600 рад/с → `T_max ≈ 17–18 Н ≈ 1.75 кгс` на мотор, TWR ≈ 10–11 для 650 г — совпадает с реальными стендами.
* **Это ключ к ощущению скорости**: на 130–150 км/ч в пике у 5" тяга падает (J растёт) → дрон «упирается» в максимальную скорость естественно, а не из-за искусственного лимита.

### 3.2 H-сила / rotor drag (обязательно!)
Лопасти, движущиеся вбок, создают силу против боковой скорости, пропорциональную оборотам — именно поэтому квадрокоптер тормозит при газе и «плывёт» на нулевом газе:
```
v_perp = проекция скорости воздуха относительно ротора на плоскость диска
F_H_i  = −k_H · Ω_i · v_perp           # k_H ≈ (1.0–2.0)e-5 Н·с/рад для 5"; масштабируется ~ D²
```
* Также даёт «момент взмаха» (blade flapping): `τ_flap ≈ −k_F · Ω_i · (ŷ × v_perp)` — нос задирается при быстром полёте вперёд (заметно у камерных дронов, компенсируется ПИДом).

### 3.3 Эффект земли (ground effect)
```
T_IGE / T_OGE = 1 / (1 − (R / (4·z))²) ,  z ≥ 0.5·R (ограничить множитель ≈ 1.4)
```
`z` — расстояние от ротора до поверхности под ним (рейкаст вниз по оси тяги каждые 2 мс). Также работает у стен/потолка как «эффект потолка» (присасывание) — бонус для бандо.

### 3.4 Вихревое кольцо и пропвош (VRS / prop wash)
Индуктивная скорость висения: `v_h = sqrt(T / (2ρA))` (для 5" ≈ 6–7 м/с, для Mavic ≈ 4 м/с).
```
λ = −V_axial / v_h                      # скорость снижения в «собственный» поток (>0 = снижаемся по оси тяги)
vrs = smoothstep(0.3, 0.8, λ) · (1 − smoothstep(1.5, 2.2, λ))
T_i *= 1 − 0.35·vrs                     # потеря тяги
шум: δT_i = T_i · 0.25 · vrs · n_i(t),  δτ = 0.02·T_hover·vrs·m_i(t)   # n,m — коррелированный шум 15–60 Гц (OpenSimplex по времени)
```
* **Пропвош** в FPV — это именно оно: при резком снижении/развороте на 180° с падением в собственный след дрон трясёт (осцилляции 20–60 Гц), гасится газом и движением вбок. Амплитуда тряски в OSD-камере + звук «булькающих» оборотов.
* Камерные дроны ограничивают скорость снижения (6 м/с) именно из-за VRS — в симе при превышении в ручном режиме дрон начнёт «сыпаться» и болтаться.

> **Реализация (`app/src/sim/aero.ts`, `drone.ts`)**: `v_h` — по тяге висения одного ротора (`m·g/n`); `T_hover` в `δτ` — тоже на ротор. Дополнительно (в формуле не было, нужно для теста §8.7): VRS гаснет при скорости в плоскости диска `μ = v_∥/v_h` от 0.35 до 0.75 — сносимый вбок след не образует кольца. Шум — `SmoothNoise` (две октавы, 22 и 46 Гц) от сидового `mulberry32`, по три независимых канала на ротор.

### 3.5 Взаимное влияние и обдув корпуса
Упрощённо: при полёте вперёд задние роторы работают в струе передних → `k_T_rear *= 1 − 0.1·smoothstep(3, 12, v_forward)`. Даёт характерный «клевок» на скорости, который пилот привык компенсировать.

---

> **Реализация**: «задние» — по направлению воздушной скорости в плоскости диска (не только вперёд): множитель `1 − 0.1·smoothstep(3, 12, v)·clamp(−cos∠(r, v)·√2, 0, 1)` (`wakeFactor`).

## 4. Аэродинамика корпуса и ветер

```
v_air = v − v_wind(p, t)                                 # относительная скорость
F_drag = −½ρ |v_air| · (C_dA)_body ⊙ v_air_body          # покомпонентно в осях тела
τ_damp = −k_ω ⊙ ω · |ω|                                   # аэродемпфирование вращения (малое)
```
* `C_dA` (м²) — вектор по осям тела `[x(бок), y(верх), z(перёд)]`. 5" freestyle с GoPro: `[0.0045, 0.012, 0.0035]`; 5" racer: `[0.0035, 0.009, 0.0025]`; Mavic-класс: `[0.008, 0.03, 0.006]`.
* Проверка калибровки: 5" freestyle на полном газе с углом 55–65° должен разгоняться до 130–150 км/ч, racer — до 160–180 км/ч, Mavic в Sport (наклон 35°) — 75 км/ч.

### Ветер и турбулентность
* Средний ветер `W(h) = W_10 · (h/10)^0.143` (степенной профиль), направление из `map.env.wind`.
* Порывы: модель **Драйдена** (MIL-F-8785C, низкие высоты) — три фильтрованных белых шума, `L_u = h/(0.177+0.000823h)^1.2`, `σ_w = 0.1·W_20`. Реализация как дискретные фильтры первого порядка на 100 Гц.
* «Механическая» турбулентность за зданиями: в `map.zones` есть объёмы `turbulence` (усиление σ ×2–3 с подветренной стороны, вихри у краёв крыш) — для бандо и города это сильно добавляет реализма.

---

> **Реализация (`app/src/sim/wind.ts`)**: `env.wind.dir_deg` — откуда дует, по часовой от севера (север = −Z, восток = +X). `W_20 := env.wind.gust_ms`. Фильтры Драйдена — точная дискретизация OU-процесса 1-го порядка на 100 Гц (стационарная σ), скорость «протягивания» поля `V = max(1, |v_air|, W(h))`. Зоны `map.zones` вида `{kind: 'turbulence', c: [x,y,z], r, gain}` умножают σ (плавно к краю). Высота профиля — `pos.y` (1…300 м).

## 5. Полётный контроллер (эмуляция Betaflight / DJI / ArduPilot-FBW)

### 5.1 Rates (стик → желаемая угловая скорость)
Стик `x ∈ [−1, 1]` после дедзоны и RC-smoothing.

**Betaflight rates** (`rc_rate`, `super_rate`, `expo`):
```
x  = x·|x|³·expo + x·(1−expo)
rr = rc_rate > 2 ? rc_rate + 14.54·(rc_rate − 2) : rc_rate
rate = 200 · rr · x
if super_rate: rate *= 1 / clamp(1 − |x|·super_rate, 0.01, 1)
```
**Actual rates** (`center_sens`, `max_rate`, `expo`) — дефолт BF 4.3+:
```
e = |x| · (x⁵·expo + x·(1−expo))
rate = x·center + max(0, max_rate − center) · e
```
**Quick rates**, **KISS**, **RaceFlight** — по исходникам Betaflight `src/main/fc/rc.c` (`applyQuickRates`, `applyKissRates`, `applyRaceFlightRates`). Игрок может вбить свои rates из Betaflight Configurator — **это главная фича для переноса навыка**. Дефолт пресета freestyle: Actual `center 70, max 670, expo 0.54` (roll/pitch), `center 70, max 500, expo 0.2` (yaw).

### 5.2 Режимы
| Режим | Что делает | Дроны |
|---|---|---|
| **Acro / Rate** | стик = угловая скорость, отпустил — дрон держит угол | все FPV |
| **Angle** | стик = угол наклона (макс. 55°), самовыравнивание | FPV (обучение) |
| **Horizon** | Angle у центра, Acro у краёв (флипы) | FPV (обучение) |
| **Air mode** | миксер держит управляемость при нулевом газе | FPV (по умолчанию вкл.) |
| **Turtle (flip over after crash)** | моторы реверсом переворачивают дрон на брюхе | FPV |
| **GPS Normal / Position** | стик = скорость (м/с), отпустил — тормоз и висение по GPS, удержание высоты | камерные, x500/Iris/Typhoon |
| **Cine / Tripod** | то же, но скорости ×0.3, плавные ускорения | камерные |
| **Sport** | наклон до 35°, скорость до 21 м/с, ослабленный тормоз | камерные |
| **ATTI** (потеря GPS) | Angle + удержание высоты, **без** удержания позиции — дрон сносит ветром | камерные (учебные ситуации) |
| **Manual (M)** | Acro с ограничителями | Avata-класс |
| **FBW-A / Cruise / Auto (waypoints)** | для самолётов/крыла: стик = крен/тангаж, автомат газа; маршрут | delta-wing, VTOL (FW-фаза) |
| **VTOL Transition** | MC → FW при V > 15 м/с, обратно — торможение и висение | standard_vtol |

### 5.3 PID и миксер (FPV)
```
e = setpoint − ω_gyro                       # гироскоп с шумом (σ ≈ 0.05–0.3 °/с) + LPF как в BF (PT1 100–250 Гц)
P = Kp·e,  I += Ki·e·dt (iterm_relax: подавление I при быстром изменении setpoint), D = −Kd·d(ω_gyro)/dt (D-term LPF)
FF = Kff · d(setpoint)/dt                   # feedforward — даёт «резкость» стиков
TPA: Kp,Kd *= 1 − tpa_rate·clamp((thr − tpa_bp)/(1 − tpa_bp), 0, 1)
anti_gravity: Ki *= 1 + ag_gain·|d(thr)/dt|
mixer (quad X, BF порядок):  m_i = thr + roll·Rx_i + pitch·Py_i + yaw·Yz_i
airmode: если max(m)−min(m) > 1 — сжать, сохранив разность; сдвинуть в [idle, 1]
```
* Стартовые PID 5" (в «единицах BF», пересчёт ×k внутри): `P 45/47/45, I 80/84/80, D 30/34/0, FF 120/125/120` — подобрать на стенде (этап 2, см. тест «step response»).
* **Важно для реализма**: настоящий FC не идеален — небольшой overshoot, bounce-back после флипа, пропвош не гасится полностью. Не делаем «идеальный» контроллер; цель — копия поведения хорошо настроенного BF-квада.

> **Реализация (Этап 2, `app/src/sim/fc/betaflight.ts`, `mixer.ts`)**:
> * Масштабы BF → физика: `P×0.8 (1/с), I×1.5, D×0.016 (с), FF×1/120` — отношение D/P ≈ 13 мс, как в BF (P×0.032, D×0.00053 → ≈11 мс). Выход PID — угловое ускорение; миксер линеаризует тягу по стационарной кривой `Ω(duty)` мотора при номинальном напряжении (`omegaCurve`): FC не знает напряжения пакета (как BF без `vbat_sag_compensation`) — свежий пак «острее», севший — «ватнее».
> * С электромеханикой отдача по газу почти постоянна (обороты «проседают» к верху газа), поэтому **TPA по умолчанию — только на D** (`tpa_mode: 'D'`, как в BF 4.3+); `'PD'` — по формуле выше.
> * Anti-gravity: `Ki ×= 1 + gain·min(1, PT1₁₅Гц|d(thr)/dt| / 5 с⁻¹)`, `fc.anti_gravity` (по умолчанию 2.5).
> * iterm_relax (режим setpoint): накопление I × `max(0, 1 − |sp − PT1₁₅Гц(sp)|/30 °/с)`.
> * Гироскоп: белый шум `sensors.gyro_noise_dps` + остаточная вибрация моторов на частоте вращения `sensors.vibration_dps·(Ω/Ω_max)²` → PT1 250 Гц (`fc.filters.gyro_lpf_hz`) → PID; D — на измерении через PT1 120 Гц (`dterm_lpf_hz`).
> * **Turtle** (`T`): моторы реверсом; мотор включается, если его обратная тяга крутит дрон по стику; expo 0.35 (`crashflip_expo` BF); как в BF 4.5, моторы сами останавливаются, когда дрон лёг на брюхо (наклон < 60°). Обратный проп — `rotors.reverse_eff` (0.3) от прямой тяги.
> * Rates: Betaflight / Actual / Quick / KISS / RaceFlight (порт `rc.c`); импорт/экспорт CLI (`set rates_type`, `roll_rc_rate`, `roll_srate`, `roll_expo`, … и старые `rc_rate`/`rc_expo`) — `app/src/sim/cli.ts`, в игре — `Ctrl+V`.

### 5.4 Камерные дроны (каскадный контроллер)
`позиция/скорость (PID 50 Гц) → желаемый наклон (лимит 25–35°) → угловой контур (PID 400 Гц) → миксер`. Плавные S-кривые ускорения (jerk-limit), тормоз до остановки ≈ 1–2 с с 15 м/с. Барометр с шумом (±0.5 м) + ToF/визуальное позиционирование < 10 м.
**Датчики препятствий** (APAS-lite): лучи вперёд/назад/вниз, торможение за `d = v²/(2·a_brake) + 1.5 м` — отключаемо в Sport (как в жизни).

### 5.5 Крыло (delta-wing / самолётная часть VTOL)
```
α = atan2(−v_air_y_body, −v_air_z_body),  β = asin(v_air_x_body/|v|)
L = ½ρV²S·C_L(α),  D = ½ρV²S·(C_D0 + k·C_L²),  Y = ½ρV²S·C_Yβ·β
C_L(α) = C_Lα·α            до α_stall ≈ 24–28° (delta — вихревой подъём, мягкий срыв), затем падение до 0.6·C_Lmax
моменты: C_m = C_m0 + C_mα·α + C_mδe·δe + C_mq·q·c/2V
         C_l = C_lβ·β + C_lδa·δa + C_lp·p·b/2V,   C_n = C_nβ·β + C_nr·r·b/2V
δe/δa — элевоны (микс: δ_L = δe + δa, δ_R = δe − δa), ход ±20°, скорость привода 200 °/с
тяга толкающего винта: та же модель пропеллера (п.3) с ДВС: P_engine(throttle) ≈ 35 кВт max, инерция газа τ ≈ 0.4 с
```
Коэффициенты для пресетов — в `DRONES.md`. Взлёт крыла: с направляющей/катапульты (стартовый ускоритель — импульс по таймеру 2 с), посадка — парашют или «на брюхо» (учебный режим). Только полётная механика и навигация по точкам — никакой боевой части/поражения целей в игре нет.

> **Реализация (Этап 3, `app/src/sim/wing.ts`, `pusher.ts`, `fc/plane.ts`, `fc/vtol.ts`)**: силы — в осях потока (сопротивление вдоль −v, подъёмная ⟂ v в плоскости симметрии), `C_D = C_D0 + max(k·C_L², C_D90·sin²α)` (непрерывный переход к обтеканию плашмя — парашют/висение VTOL в ветер). За срывом `C_L` падает с наклоном `CLa_stall` (PX4) или линейно до `CL_post_ratio·C_Ls` за `stall_width_deg`, но не ниже `CL_post_ratio·C_Ls·sin 2α` (0 при 90°). В моментах `sin α`/`sin β` вместо α/β (ограничены на больших углах); демпфирующие члены записаны как `ρ V S c² C_mq q / 4` — конечны при V → 0. ДВС: `τ = throttle·P_max/Ω_max` (мощность ∝ оборотам, пик на номинале), ограничитель +3 %, `J_rot Ω̇ = τ − k_Q(J)Ω²`; электрический толкающий — первый порядок, ток из механической мощности (на ту же батарею, что подъёмные). Ускоритель — тяга вдоль носа через ЦТ; направляющая — одна степень свободы (кинематически, до схода). Парашют: `F = −½ρ|v| cdA·k² v` в точке подвеса `recovery.attach` (маятниковая устойчивость), раскрытие k: 0→1 за `deploy_s`. FBW: модельная инверсия `δ = I·ε̇/(q̄ S c C_mδ)` + балансировка по оценке α для текущей перегрузки — как миксер мультикоптера, коэффициенты усиления одинаково работают на любой скорости.

## 6. Датчики, связь, видео

* **Гироскоп/акселерометр**: шум + смещение + вибрации от моторов (гармоники `Ω_i/2π`, амплитуда ∝ дисбаланс; при повреждённом пропе ×5) — вибрации идут в D-term → «горячие моторы»/дрожь картинки как в жизни.
* **RF-модель** (приёмник управления и видео):
  `PL(dB) = 20·log10(d) + 20·log10(f) − 147.55 + Σ L_obst` (FSPL + потери на препятствиях по рейкастам: бетон 12–20 дБ, кирпич 8–12, металл 25+, деревья 0.5 дБ/м).
  `RSSI = P_tx + G_tx + G_rx − PL`. Пороги: ELRS 2.4 ГГц −105 дБм (250 Гц) … −112 (50 Гц); 915 МГц лучше пробивает стены.
  Видео 5.8 ГГц аналог: SNR → шум/полосы/срыв синхры (шейдер), цифра: SNR → битрейт → пикселизация/фризы/задержка.
  **Failsafe**: потеря линка > 0.3 с → стадия 1 (держать стики), > 1.5 с → дизарм (FPV) / RTH (камерные).
* **Задержка видео**: аналог 15–25 мс, цифра 25–40 мс (DJI O3/Walksnail), спутник — нет. Реализация: кольцевой буфер кадров рендер-таргета, показ кадра `t − latency`.
* **Камера FPV**: FOV 150° (4:3) / 155° (16:9) с бочкообразной дисторсией (шейдер, параметр k1 ≈ −0.32), уптилт 0–50°, motion blur от rolling shutter опционально.

## 7. Столкновения и повреждения

* Движок коллизий: **Rapier3D** (`@dimforge/rapier3d-compat`). Дрон = динамическое тело с составным коллайдером: бокс рамы + сфера/цилиндр на каждый пропеллер (сенсоры для «удара пропом»). Карта = статические OBB/цилиндры/heightfield из `maps/<id>/<id>.json` (дёшево на телефоне) или trimesh для сторонних карт (Sketchfab).
* Rapier используется для **обнаружения контактов и разрешения проникновений**; аэродинамика и моторы — наши силы, подаются через `addForce/addTorque` перед каждым `world.step()` с `dt = 1 ms`. CCD включён (дрон летит 50 м/с, стена 0.3 м).
* Материалы: трение 0.4–0.9, упругость 0.05–0.3 (бетон/металл/трава/вода).
* **Повреждения** (от импульса удара `J` и скорости ротора):
  * удар пропеллера > `J_prop` → проп повреждён: `k_T *= 0.5–0.8` + дисбаланс (вибрации), > `2·J_prop` → проп сломан (тяга 0);
  * удар рамы > `J_arm` (5" ≈ 6 Н·с, 10" ≈ 20 Н·с) → «отломан луч» → мотор отключён → неуправляемость (конец полёта);
  * камера: смещение угла уптилта при сильном ударе в нос;
  * батарея: выброс пакета при ударе сверху (дрон легче, выключение);
  * режим «аркада»: повреждения выкл.; «реализм»: вкл.; «хардкор»: + перегрев, усталость пака, ремонт в ангаре.
* Вода: при касании — тонет/короткое замыкание (FPV), Mavic — выключение.

## 8. Валидация (как проверяем «как в жизни»)

> **Статус (Этап 2, `app/test/physics.test.ts`, 5" freestyle)**: висение 0.18 (эталон 0.21) · панч +100 м за 2.86 с, минимум на OSD 21.4 В (сырое напряжение кратко ниже) · макс. скорость 141 км/ч на 62° · ступенька 80 °/с: подъём 25 мс, перерегулирование 5 %; 300 °/с: 32 мс, 1 % · флип 360° за 0.57 с, потеря высоты 1.3 м (свободное падение за флип — 1.5 м; airmode на «верхних» половинах держит часть) · висение ≈ 9 мин, фристайл 2.6 мин · пропвош 71 °/с против 3 °/с при 5 м/с вбок. Остальные FPV: висение и стабильность (Angle — выравнивание с 25°, Acro — полный стик) — зелёные.

Автотесты `app/test/sim/*.test.ts` (vitest), прогон в CI:
1. **Hover**: газ висения 5" freestyle ≈ 18–25 %, Mavic ≈ 45–55 % (батарея 100 %).
2. **Вертикальный панч**: 5" с 0 до 100 м за ~2.4–3.0 с; падение напряжения 6S до 21–22 В.
3. **Макс. скорость** (горизонт, полный газ, оптимальный угол): см. таблицу `DRONES.md`, допуск ±10 %.
4. **Step response** roll-контура: время нарастания 15–25 мс, overshoot < 10 % (5" BF-пресет).
5. **Флип 360° по roll** при rate 670 °/с: ~0.55–0.65 с, потеря высоты на нулевом газе ≈ 1.5–2.5 м.
6. **Время полёта**: 5" 6S 1100 при висении ≈ 5–6 мин, агрессивный фристайл 2.5–3.5 мин; Mavic-класс ≈ 40+ мин; 7" Li-ion ≈ 15–25 мин.
   *Этап 2*: модель даёт висение ≈ 9 мин до LVC — по теории импульса (идеальная мощность 42 Вт, FoM ≈ 0.45, КПД мотора ≈ 0.75 → ≈ 150 Вт ≈ 6.6 А) это физичное значение для 620 г на 1100 мА·ч; «5–6 мин» — скорее спокойный полёт. Тест допускает 5–9.5 мин; фристайл (профиль: каждые 3.5 с — 0.5 с панч, флип на нуле, возврат) — 2.6 мин ✓.
7. **Пропвош**: снижение 8 м/с вертикально вниз на газе 10 % → амплитуда угловых колебаний > 40 °/с (5"), при горизонтальной скорости 5 м/с — < 15 °/с.
8. **Сравнение с реальными логами**: импорт Blackbox-логов Betaflight (CSV после `blackbox_decode`) → прогон тех же стиков через сим → сравнение `gyro` и `motor` (RMSE). Это этап 5 «калибровка по реальным данным»; инструмент — `tools/blackbox_compare.ts`.
