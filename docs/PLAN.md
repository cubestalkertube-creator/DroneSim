# DroneSim — мастер-план

> Реалистичный симулятор управления дронами для обучения и практики. ПК (Windows/macOS/Linux) + телефоны (Android/iOS), нативные сборки. Управление: клавиатура/мышь, тач, геймпад, настоящий RC-пульт по USB.
>
> Этот документ — задание для следующих сессий разработки. Порядок работ — раздел 12 (этапы). Физика — [`research/PHYSICS.md`](research/PHYSICS.md), дроны — [`research/DRONES.md`](research/DRONES.md), ассеты — [`ASSETS.md`](ASSETS.md), дизайн — [`design/`](design/).

---

## 1. Видение и принципы

1. **Физика первична.** Навык должен переноситься на реальный дрон: те же rates Betaflight, та же просадка батареи, тот же пропвош, тот же тормозной путь DJI. Всё, что «ощущается», должно быть следствием модели, а не скриптом.
2. **Обучение, а не только игра.** Академия уроков от «что такое стики» до power loop в бандо; объективные метрики (плавность, удержание высоты, точность), повтор и разбор полёта.
3. **Везде нативно и быстро.** 60 FPS на среднем Android-телефоне, 120+ FPS на ПК. Физика 1 кГц независимо от FPS.
4. **Современный минималистичный дизайн**: тёмный интерфейс, крупная типографика, один акцентный цвет, никакого «геймерского» шума.
5. **Честные лицензии**: все ассеты — CC0/CC-BY/собственные, титры генерируются из `CREDITS.json`.

## 2. Выбор технологий (решение)

### Сравнение
| Вариант | + | − | Вердикт |
|---|---|---|---|
| Unity | редактор, мобилки, физика | тяжело и дорого работать через ИИ (сцены/префабы бинарны/YAML), лицензия, PhysX не годится для 1 кГц дрона «из коробки» | нет |
| Unreal | графика | огромный, C++/Blueprints, мобилки тяжело, медленная итерация | нет |
| Godot 4 | открытый, экспорт везде | сцены .tscn + GDScript/C#, своя физика всё равно нужна, сложнее ИИ-автоматизация, WebView-UI нет | запасной |
| **TypeScript + three.js + Rapier (WASM), обёртки Tauri 2 (ПК) и Capacitor (мобилки)** | весь проект — текст (идеально для ИИ), мгновенная итерация (Vite HMR), WebGL2/WebGPU, AudioWorklet для синтеза звука моторов, Gamepad API (RC-пульты как джойстики), один код на все платформы, UI на HTML/CSS (быстро сделать красиво) | своя сцена/рендер-пайплайн, нужно следить за производительностью на мобилках | **ВЫБРАНО** |

### Стек
* **Язык**: TypeScript 5 (strict). Сборка: **Vite 6**. Тесты: **Vitest**. Линт: ESLint + Prettier.
* **Рендер**: **three.js** (r17x, WebGL2; WebGPU-рендерер как опция для ПК после стабилизации). Постобработка: `postprocessing` (bloom, SMAA, vignette, хроматическая аберрация для FPV-камеры), свой шейдер дисторсии fisheye и «аналогового шума».
* **Физика коллизий**: **@dimforge/rapier3d-compat** (WASM, детерминированный). Аэродинамика/моторы/FC — свой код (`src/sim`).
* **Звук**: Web Audio API + **AudioWorklet** (процедурный синтез моторов по RPM) + сэмплы (ветер, удары, эмбиент).
* **UI**: лёгкий реактивный слой — **Preact + Signals** (или чистый TS + lit-html) поверх канваса; CSS-переменные дизайн-системы из `docs/design/`.
* **Хранение**: IndexedDB (настройки, прогресс, реплеи, rates-профили), экспорт/импорт JSON.
* **Сборки**:
  * ПК: **Tauri 2** (Rust-оболочка, системный WebView2/WKWebView/WebKitGTK; инсталлер ~10 МБ + ассеты). Альтернатива при проблемах с WebView на Linux — Electron.
  * Android/iOS: **Capacitor 6** (WebView, нативные плагины: haptics, keep-awake, screen-orientation, gamepad fallback). Альтернатива — Tauri 2 mobile.
  * Web/PWA — та же сборка (удобно для тестов и демо).
* **Ассеты**: glTF/GLB (Draco/Meshopt + KTX2 текстуры через `gltf-transform` в `tools/pipeline/`), HDRI → предфильтрованные cubemap/PMREM в рантайме или `.ktx2` заранее для мобилок.

## 3. Архитектура

```
app/
  index.html
  src/
    main.ts                 # bootstrap, выбор профиля качества, роутинг экранов
    core/                   # GameLoop (fixed-step 1 кГц + render), EventBus, Time, PRNG, Settings, Storage, i18n
    sim/                    # ЧИСТАЯ физика, без three.js (можно гонять в Node/воркере/тестах)
      rigidbody.ts          # 6DoF, кватернионы
      motor.ts, battery.ts, propeller.ts, aero.ts, wind.ts (Dryden), groundEffect.ts, vrs.ts
      fc/ betaflight.ts (rates, PID, mixer, airmode, TPA, antigravity, turtle), gps_consumer.ts, px4.ts, fixedwing.ts, vtol.ts
      sensors.ts (IMU шум/вибро), rf.ts (линк/видео), damage.ts
      drone.ts              # сборка дрона из пресета drones.json
      world.ts              # Rapier world, коллайдеры карты, рейкасты
    input/                  # InputManager: keyboard, mouse, touch (virtual sticks), gamepad/RC (Gamepad API), calibration, mapping, curves
    render/                 # three.js сцена, загрузка GLB, материалы из layout.materials, HDRI/небо, тени (CSM), пропеллер-блюр, FPV-шейдеры, LOD, quality presets
    camera/                 # FPV (uptilt, fisheye, latency buffer), Chase, Orbit, LOS (вид с земли), Free/Replay
    audio/                  # AudioEngine, motorSynth.worklet.ts, sampleBank, spatial (PannerNode), reverb зон
    game/                   # режимы: FreeFlight, Academy, Race, Freestyle, Mission, Photo, LongRange; RaceTimer, Gates, TrickDetector, Scoring, Replay/Ghost
    ui/                     # экраны (Preact): Splash, Main, Play, MapSelect, DroneSelect, Hangar, Settings, Academy, Pause, Results, Credits; HUD/OSD
    platform/               # Tauri/Capacitor мосты: fullscreen, orientation, haptics, файлы
  public/assets -> ../assets (симлинк/копирование в сборке)
  test/                     # vitest: sim/*, input/*, game/*
tools/                      # ассет-пайплайн, Blender-скрипты, фетчеры
```

**Поток данных**: `Input → ControlFrame{throttle,yaw,pitch,roll,aux[8]} → sim.fc → sim.motors → sim.rigidbody(+Rapier) → SimState → (render, audio, HUD)`. Симуляция не знает о three.js; рендер читает `SimState` с интерполяцией (`alpha = acc/dt`).

**Физика в Web Worker** (этап 3, сделано): `sim` работает в воркере (`core/sim.worker.ts` → `sim/serve.ts` → `SimHost`), главный поток — рендер/ввод/звук через `core/simClient.ts`. Обмен — postMessage (команды + стики + число шагов → снимок состояния с двумя последними шагами для интерполяции); SharedArrayBuffer не используется: нужен COOP/COEP, которого нет в WebView Capacitor.

## 4. Физика и управление полётом
Полная спецификация — [`research/PHYSICS.md`](research/PHYSICS.md). Ключевое:

## 5. Управление (ввод)

### 5.1 Общая модель
`ControlFrame` = 4 оси [−1..1] (throttle [0..1] для FPV) + 8 AUX-каналов (arm, mode, beeper, turtle, camera tilt, RTH, photo, record). Всё как у реального приёмника → режимы и арминг работают через AUX, как в Betaflight.

### 5.2 Клавиатура + мышь (ПК)
Клавиатура дискретна, поэтому делаем **«аналоговую эмуляцию»**: нажатие плавно ведёт ось к цели со скоростью `slew` (настраивается), отпускание — к центру (кроме газа FPV).

| Действие | Mode 2 по умолчанию |
|---|---|
| Газ +/− (FPV: держится; GPS: самоцентр) | `W` / `S` (Shift — быстрее, Ctrl — точнее) |
| Рысканье (yaw) | `A` / `D` |
| Тангаж (pitch) | `↑` / `↓` или `I` / `K` |
| Крен (roll) | `←` / `→` или `J` / `L` |
| Арм / дизарм | `Пробел` (удержание 0.3 с — защита) |
| Режим полёта (Acro/Angle/Horizon; C/N/S) | `1` / `2` / `3` |
| Камера: FPV / от 3-го лица / LOS / свободная | `C` (цикл), `V` — уптилт ±5° |
| Turtle mode | `T` |
| RTH / посадка (GPS) | `H` / `G` |
| Подвес камеры (GPS) | колесо мыши |
| Рестарт с точки старта | `R`, пауза — `Esc` |
| **Режим «мышь как правый стик»** | `M`: движение мыши = pitch/roll (с пружиной к центру), колесо = газ |

Отдельный пресет **«Новичок»**: Angle + авто-газ (удержание высоты) — клавиатура становится комфортной. Для Acro на клавиатуре — рекомендация купить/подключить геймпад (подсказка в UI).

### 5.3 Геймпад и настоящий RC-пульт
* **Gamepad API**. RC-пульты (RadioMaster, TBS, Jumper, FrSky на EdgeTX/OpenTX) в режиме **USB Joystick (HID)** определяются как геймпад — это главный путь для серьёзных пилотов.
* **Мастер калибровки**: «подвигайте все стики до упора» → min/max/центр, автоопределение осей и инверсии, назначение тумблеров на AUX (как вкладка Receiver/Modes в Betaflight). Профили по `gamepad.id`.
* Дедзона, expo, RC-smoothing (как BF `rc_smoothing`), вывод «сырых» значений каналов в настройках (живые полоски).
* Xbox/PS-геймпады: Mode 2 раскладка, газ — левый стик с опцией «самоцентр/не центр», триггеры — газ для новичков.
* Мобилки: Bluetooth-геймпады (Gamepad API работает в Android WebView/WKWebView; если нет — нативный плагин Capacitor, этап 4).

### 5.4 Телефон (тач)
* **Два виртуальных стика** (мультитач, Pointer Events): левый — газ/рысканье, правый — тангаж/крен. Газ FPV — без пружины (палец держит положение), GPS — с пружиной. Размер/прозрачность/положение — настраиваются (редактор раскладки перетаскиванием). Плавающий центр (стик появляется там, где коснулся) — опция.
* Хаптика (Capacitor Haptics): лёгкий клик при пересечении центра/дедзоны, вибрация при ударе.
* Кнопки: ARM (свайп-слайдер, чтобы не нажать случайно), режим, камера, RTH, фото.
* Опция «гироскоп телефона = правый стик» (DeviceOrientation, калибровка нуля).
* Ландшафтная ориентация, wake-lock, поддержка вырезов (safe-area-inset).

## 6. Камеры и видео-реализм
| Камера | Описание |
|---|---|
| **FPV** | точка `fpv_cam` модели, уптилт из пресета/настроек, FOV 120–155°, дисторсия fisheye, задержка (буфер кадров), аналог: шум/полосы/срыв синхры по RSSI/SNR, цифра: пикселизация/фризы; OSD Betaflight-стиля |
| **Gimbal (GPS-дроны)** | стабилизированная камера, наклон колесом/слайдером, режимы Follow/FPV/Lock, HUD как в DJI Fly (без бренда) |
| **Chase (3-е лицо)** | пружинная камера сзади-сверху (обучение/аркада) |
| **LOS (с земли)** | камера на «пилоте» на точке старта, следит за дроном — тренировка полёта на прямой видимости (с риском потерять ориентацию, как в жизни) |
| **Free / Replay / Photo** | свободная камера для реплеев и фото-режима |

**OSD (FPV)**: напряжение/банка, mAh, таймер, RSSI/LQ, газ %, высота, скорость, стрелка домой, дистанция, авиагоризонт (опц.), прицел, предупреждения (LOW BAT, RXLOSS, LAND NOW). Элементы перетаскиваются, как в OSD-редакторе Betaflight.
**HUD (GPS)**: высота/дистанция/скорость (H.S/V.S), спутники, % батареи и прогноз времени, мини-карта с домом, индикатор ветра, датчики препятствий (дуги).

## 8. Режимы игры и обучение

### 8.1 Академия (главный режим обучения)
Последовательные уроки с целями, подсказками-оверлеями и оценкой (0–3 звезды). Прохождение открывает дроны/карты.
1. **Пульт и стики**: что делает каждый стик (визуализация стиков на экране), арминг, режимы. Камерный дрон.
2. **Висение** (GPS): взлёт на 2 м, удержать в круге 10 с; посадка на «H».
3. **Ориентация**: «носом к себе» (LOS-камера), восьмёрка, облёт столба.
4. **ATTI без GPS**: висение со сносом ветром.
5. **Съёмка**: орбита вокруг объекта с постоянной скоростью, плавный «reveal».
6. **FPV Angle**: пролёт через ворота, слалом.
7. **Acro: газ**: удержание высоты в Acro (самое сложное для новичка), «кольцо» по полю.
8. **Acro: повороты**: координированный разворот (крен + yaw), split-S.
9. **Трюки**: flip, roll, power loop, dive с трубы, matty flip, juicy flick (TrickDetector распознаёт по траектории/ориентации).
10. **Бандо**: пролёт через окна, гапы, лестничные пролёты; пропвош — как с ним бороться.
11. **Long Range**: батарея, RF-тени, GPS Rescue, возврат по стрелке.
12. **Крыло/VTOL**: взлёт, переход, маршрут, посадка; ветер и снос.
Метрики: время, точность, плавность (интеграл |jerk|), удержание высоты (RMSE), столкновения, расход батареи.

### 8.2 Остальные режимы
* **Свободный полёт** — любая карта/дрон/время суток/ветер, мгновенный рестарт, телепорт к спавнам.
* **Гонка** ✅ — трассы из ворот (`layout.gates` порядок = трасса), Time Trial, «призрак» лучшего круга, сплиты, штраф за пропуск ворот (или незачёт). Редактор трасс (этап 5): ставим ворота на карте в рантайме, сохраняем JSON.
* **Фристайл** — очки за трюки и близость к препятствиям (proximity по рейкастам), комбо, линии `zones.trick_line`.
* **Миссии** — гражданские задачи: инспекция (облететь объект, сфотографировать N точек), поиск человека (термокамера), доставка груза в зону (10"), картография по сетке (x500 Mission), обнаружение утечки на трубопроводе.
* **Фото/видео** — камерные дроны, фото-режим с оценкой композиции (правило третей).
* **Реплеи** — запись `ControlFrame + SimState` 50 Гц, перемотка, свободная камера, экспорт ролика (MediaRecorder).

## 9. Интерфейс и дизайн
Подробно и макеты — [`design/DESIGN.md`](design/DESIGN.md) и интерактивный макет [`design/ui_mockup.html`](design/ui_mockup.html).

* Мобильная адаптация: всё управляется пальцем, минимум 44 px цели, safe-area.

## 10. Звук
* **Моторы — процедурный синтез** (AudioWorklet): на каждый мотор — основная гармоника `f = RPM/60 · blades` + гармоники ×2…×6, шум лопастей (полосовой шум ∝ тяге), «жужжание» обмоток (ШИМ-свист), модуляция при пропвоше/повреждённом пропе. Смешивание с сэмплами из `assets/audio/motors_*` (кроссфейд по RPM — гранулярный ресемплинг петель) → максимально узнаваемый «вой» квада.
* Доплер и пространственность (PannerNode HRTF) для внешних камер, «звук в очках» (FPV: тише, приглушён) — как реально слышит пилот.
* Ветер по скорости (шум с фильтром), удары (по материалу: бетон/металл/трава/вода), бипы ESC при арме/потере связи, VTX-шум (аналоговая статика при плохом сигнале), эмбиент карты (город/завод/поле), реверб помещений (`env.indoor_reverb`).
* Источники: Freesound (CC0/CC-BY, `assets/audio/CREDITS.json`), для релиза — заменить превью на оригиналы WAV (скрипт с API-ключом Freesound) и/или собственные записи.

## 11. Графика и производительность
* PBR (MeshStandardMaterial / Physical), HDRI-освещение + солнце с каскадными тенями (CSM, 2–4 каскада), туман/атмосфера (экспоненциальный), SSAO на ПК, bloom для LED.
* Пропеллеры: реальные лопасти при < 1500 RPM → диск `rotor_N_blur` с вращающейся альфа-текстурой выше.
* LOD: деревья/пропсы (2–3 уровня, `gltf-transform simplify`), импосторы для дальних деревьев.
* Профили качества: **Low** (мобилки: 1k текстуры, 1 каскад тени 1024, без SSAO, рендер 0.75×, физика 500 Гц), **Medium**, **High**, **Ultra** (WebGPU, 4k HDRI).

## 13. Риски и решения
| Риск | Решение |
|---|---|
| Производительность физики 1 кГц в JS на телефоне | Профиль 500 Гц, воркер, без аллокаций в горячем цикле (пулы векторов, `Float64Array`), Rapier только для контактов |
| Gamepad API в WebView (особенно iOS) | Проверить на этапе 3; фолбэк — нативный плагин (GCController / Android InputDevice) |
| Тяжёлые сторонние модели (430k–1.7M треугольников) | Пайплайн simplify + meshopt + KTX2, LOD, ограничение бюджета, импостеры |
| «Неправильное ощущение» физики | Тесты PHYSICS §8 + плейтесты с FPV-пилотами + сравнение с Blackbox |
| Лицензии CC-BY / NC | Автотитры из CREDITS.json; NC-модели (Shahed со Sketchfab) не включать в коммерческую сборку — есть своя модель |
| Объём ассетов в мобильной сборке | Загрузка карт по требованию (Capacitor: assets в APK ≤ 1 ГБ или скачивание при первом запуске), 1k-текстуры для мобилок |

## 14. Соглашения для разработчиков (и ИИ-сессий)
* Координаты игры: +Y вверх, −Z вперёд, метры. Blender: +Z вверх, +Y вперёд (экспортёр glTF сам конвертирует).
* Узлы моделей: `rotor_<i>` (+`_blades`, `_blur`), `fpv_cam`, `elevon_L/R`, custom props (`spin`, `diameter_m`, `uptilt_deg`) — читаются из glTF extras.
* Пресеты — только в `assets/presets/drones.json`; никаких магических чисел в коде.
* `sim/` не импортирует three.js/DOM. Каждая физическая формула — с тестом.
* Коммиты маленькие, по одному модулю; на каждом этапе обновлять чек-листы этого файла.
